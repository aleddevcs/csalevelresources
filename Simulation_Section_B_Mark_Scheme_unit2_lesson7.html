1Setting up a data structureBeachHuts.py, lines 21–22, 61, 67, 72, 77

Each text box has a StringVar — a variable linked to its Entry widget that holds whatever the user types into it. HutVar, HirerVar and PhoneVar are declared global so that the save and count routines, which are separate from makeWindow, can read them. HireCount and CountNeeded are integer counters, initialised to 0 before any counting starts.

2Creating a new blank fileBeachHuts.py, line 13

Hire.txt is opened in append mode ("a"). If it does not exist yet, Python creates a new blank file; if it does, the new record is added to the end without overwriting what is already stored. fileObject is the file handle used to write to it.

3Copying data from screen textboxes to data structureBeachHuts.py, lines 6, 8, 10

.get() copies the text currently typed in each box out of its StringVar into an ordinary string variable — HutSave, HirerSave and PhoneSave — so that the program can process it. This is done for every field before anything is written to the file.

4Writing of data to fileBeachHuts.py, lines 7, 9, 11, 14–15

.ljust(50) pads each field with spaces to exactly 50 characters, making a fixed-length record, so every field starts at the same position. The three padded fields are concatenated into one string with a new-line character (\n) and written as one line with write(). close() then saves the file and releases it.

5Retrieving data from fileBeachHuts.py, lines 38–40, 42–43, 45–46, 48

The file is opened for reading inside try / except, so a missing file raises an IOError that is handled with an error message instead of crashing the program. In the else part, readline() reads one record (one line) at a time — sequential access. An empty string means the end of the file has been reached, so the file is closed and break ends the loop.

6Splitting into array/textboxes/variablesBeachHuts.py, lines 49, 51, 53

Each record is split into its fields using slicing: [0:50] is the hut ID, [50:100] the hirer and [100:150] the phone number. This only works because every field was padded to 50 characters when it was saved, so each field is always in the same position. The in operator then tests whether the text typed is found inside that field — a partial match.

7Looking/counting of items requiredBeachHuts.py, lines 28, 44, 55–57

CountNeeded counts how many boxes the user filled in. For every record, CountGot is reset to 0 and then increased by 1 for each filled-in box that matches its field. If CountGot equals CountNeeded, every box that was filled in matched, so HireCount is incremented. When the loop ends the total is displayed in a message box.

8Validation (left or trim)BeachHuts.py, lines 27, 34–35, 40

A presence check: if CountNeeded is 0 nothing has been entered, so an error message is shown and return ends the routine before the file is read. The not ... == "" tests stop an empty box matching every record, because an empty string is found inside every string. The try / except also checks that the file exists before it is read. (This program has no left or trim check — annotate what is there.)

Model program (earns all eight points)

One approach among many. It uses the valid-flag style and with open from the videos, a text menu for the interface, and a record of 3 + 20 + 11 = 34 characters.

# HutBookings.py - Barry Island Beach Huts
# Records hut bookings in bookings.txt and finds a booking by hut ID.

option = ""

# LOOP: the menu keeps showing until the user chooses to exit
while option != "3":
    print("\n=== Barry Island Beach Huts ===")
    print("1. Add a booking")
    print("2. Find a booking by hut ID")
    print("3. Exit")
    option = input("Choose an option (1-3): ")

    if option == "1":

        # INPUT + LENGTH CHECK: hut ID must be exactly 3 characters
        valid = False
        while valid == False:
            hut = input("Hut ID (3 characters, e.g. H07): ")
            if len(hut) != 3:
                print("The hut ID must be exactly 3 characters.")
            else:
                valid = True

        # INPUT + LENGTH CHECK: name must be 1 to 20 characters
        valid = False
        while valid == False:
            hirer = input("Hirer's name (up to 20 characters): ")
            if hirer == "":
                print("The name cannot be empty.")
            elif len(hirer) > 20:
                print("The name must be 20 characters or fewer.")
            else:
                valid = True

        # INPUT + LENGTH CHECK: phone must be exactly 11 characters, digits only
        valid = False
        while valid == False:
            phone = input("Phone number (11 digits): ")
            if len(phone) != 11:
                print("The phone number must be exactly 11 characters.")
            elif not phone.isdigit():
                print("The phone number must be digits only.")
            else:
                valid = True

        # FIXED-LENGTH RECORD: 3 + 20 + 11 = 34 characters
        record = hut.ljust(3) + hirer.ljust(20) + phone.ljust(11)

        # CREATES THE DATA FILE and STORES ON DISK: append mode creates
        # bookings.txt if it does not exist, and adds to the end if it does
        with open("bookings.txt", "a") as file:
            file.write(record + "\n")

        # DESCRIPTIVE FEEDBACK
        print("Booking saved: hut", hut, "for", hirer, "- stored in bookings.txt")

    elif option == "2":
        key = input("Hut ID to find: ")

        # RETRIEVES DATA FROM DISK, then picks out the SPECIFIED hut
        try:
            with open("bookings.txt", "r") as file:
                found = False
                for line in file:
                    if line[0:3] == key:
                        print("Hut", key, "- hirer:", line[3:23].strip(), "- phone:", line[23:34].strip())
                        found = True
                if found == False:
                    print("No booking found for hut", key)
        except FileNotFoundError:
            print("There are no bookings saved yet.")

    elif option == "3":
        print("Goodbye!")

    else:
        print("Please choose 1, 2 or 3.")
