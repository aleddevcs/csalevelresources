Upgrading Validation

~10 minutes

BEAT 1 · WHY CHANGE IT

Ask: "Last lesson every rule had its own loop. What happens if a visitor gets past one loop, then breaks a different rule in the next?"

Land the point: separate loops each check only their own rule. One loop re-checks every rule on every attempt, and each rule gets its own message.

BEAT 2 · LIVE-CODE THE NAME FIELD

Say: "One flag, one loop, one if/elif chain — the field is only valid when every rule has passed."

valid = False
while valid == False:
    name = input("Name: ")
    if name == "":
        print("Name cannot be empty.")
    elif len(name) > 20:
        print("Name must be 20 characters or fewer.")
    else:
        valid = True
Expect:Blank input prints the empty message; 25 letters prints the length message; a normal name moves on.

BEAT 3 · MORE RULES, SAME LOOP

Say: "To add a rule, add an elif. Order matters: empty first, then type or format, then length."

valid = False
while valid == False:
    date = input("Hire date (dd/mm/yyyy): ")
    if date == "":
        print("Date cannot be empty.")
    elif date.count("/") != 2:
        print("Date must be in the format dd/mm/yyyy.")
    elif len(date) > 10:
        print("Date must be 10 characters or fewer.")
    else:
        valid = True
Expect:Each broken rule shows its own message; only a valid date ends the loop.
Ask: "Why must the maximum length match the .ljust() width?" — a longer value spills into the next field and every slice after it is wrong.
Common slip: Forgetting valid = False before the next field's loop — the loop is skipped because the flag is still True.

Context Managers

~10 minutes

BEAT 1 · REWRITE THE SAVE CODE

Say: "Same job, but the file closes itself when the with block ends — even if something goes wrong. No file.close() to forget."

with open("kayak_hires.txt", "a") as file:
    file.write(record + "\n")

print("Saved", name, "to kayak_hires.txt")
Expect:Two records give two lines in kayak_hires.txt, and the confirmation names the visitor and the file.
Point out: Append mode creates the file if it doesn't exist yet — that's the "creates a data file" mark. The descriptive confirmation is a separate mark.

BEAT 2 · THE EXAM'S STYLE, BESIDE IT

Say: "The starter code in 'complete the code' does the same job the older way. You need to read and complete it."

fileObject = open("kayak_hires.txt", "a")
fileObject.write(record + "\n")
fileObject.close()
try:
    fileObject = open("kayak_hires.txt", "r")
except IOError:
    print("No file to read")
else:
    while True:
        record = fileObject.readline()
        if record == "":
            fileObject.close()
            break
        # ...check the fields in record here...
Expect:Nothing new to learn — open, read a line at a time, stop at the empty string, close.
Ask: "How does the program know it has reached the end of the file?" — readline() returns an empty string.

Retrieving a Record

~10 minutes

BEAT 1 · READ AND SLICE

Say: "We read the file one line at a time, slice out the name, strip the padding and compare it to what we searched for."

search_name = input("Visitor name: ")
found = False

with open("kayak_hires.txt", "r") as file:
    for line in file:
        if line[0:20].strip() == search_name:
            print("Name:", line[0:20].strip())
            print("Kayak:", line[20:35].strip())
            print("Date:", line[35:45].strip())
            found = True
Expect:A record saved once prints once; saved twice prints twice, each with labelled fields.
Ask: "Where do 0, 20, 35 and 45 come from?" — the .ljust() widths: 20, then 15, then 10.

BEAT 2 · WHEN NOTHING MATCHES

Say: "If found is still False after the loop, nothing matched — so tell the user."

if found == False:
    print("No matching hire found.")
Expect:A name that isn't in the file prints the message once, after the whole file has been checked.

BEAT 3 · BREAK IT, THEN FIX IT

Say: "Rename kayak_hires.txt and run Retrieve." Let it crash with FileNotFoundError, then wrap it:

try:
    with open("kayak_hires.txt", "r") as file:
        for line in file:
            ...   # same loop as before

    if found == False:
        print("No matching hire found.")
except FileNotFoundError:
    print("No hires saved yet.")
Expect:With the file missing: "No hires saved yet." With the file present: normal results or "No matching hire found." — never both messages.
Common slip: Putting the found check after the try/except prints two messages when the file is missing. Keep it inside the try.

BEAT 4 · STRETCH FOR FAST PAIRS

Counting the matches previews the 'counting found items' and 'outputting number counted' marks in complete-the-code questions.

count = 0

with open("kayak_hires.txt", "r") as file:
    for line in file:
        if line[0:20].strip() == search_name:
            count += 1

print(count, "hire(s) found for", search_name)
Expect:"2 hire(s) found for Aled" when that name has been saved twice.
