Build It: Fix, Count, Annotate

Four parts: fix Stock.py, fix Volunteers.py, write the count routine, then annotate pupils.py. Tick each box as you complete it.

ScenarioThe exam's own starter files
FilesStock.py, Volunteers.py, count_routine_starter.py, pupils.py

Before you start: have the files open and the Template Anatomy card next to you. tkinter windows won't open in Codespaces — you don't need them to. Completing the code and checking it against the answer key is the task.

1

Fix the Code: Stock.py

Stock.py is a 2022 exam starter file with 8 gaps, each marked . . .. Complete every one on your own, and write your answers as you go.

Don't open the answer key until you've filled in every gap. A wrong guess that you then correct teaches you more than a copied answer.

The five gap types
TypeGapLook here
1A name that must match its neighboursThe sibling lines — same code, one field over
2A method name (.get, .ljust, .showinfo)The same method on the lines around it
3A counter increment (CountGot +=1)The sibling lines use the same counter
4A function name that must match command=The Button's command=, or the def line
5A file name that must matchWhere the file was opened for saving

The method: find the sibling lines → copy the pattern → still stuck? Ctrl+F — the missing word is almost always somewhere else in the file.

Common slips A missing full stop before ljust; quote marks around a variable name; showinfo without the messagebox. in front.

Write the Count Routine

Write the template's count routine yourself, as a console program that runs anywhere. Open count_routine_starter.py and keep Member.txt (10 records, three fields of 50 characters) in the same folder.

First, the hand-trace: work out what the routine should give before you code it — open the hand-trace sheet. Then follow the TODOs in order, testing as you go.

4

Annotate: pupils.py

Annotation is marked in every paper. Open pupils.py and the annotation practice sheet, and annotate the eight routines: name each one, say what the code does beyond what the variable names say, and use technical terms.

When you've finished, open the model annotation and compare.

Common slip “Opens the file.” only says what the code already says. “Opens the file in append mode, which creates it if it doesn't exist and adds to the end” earns the mark.
