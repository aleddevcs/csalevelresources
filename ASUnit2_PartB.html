Python Scratch-Build Mastery

This version is organised more like a teaching sequence: start with the template, then move into inputs, validation, saving in a fixed-width format, and finally retrieval. The aim is to keep the code practical and exam-friendly rather than over-engineered.

Step 1

Build the structure first

Menu, add option, retrieve option, exit option. Students should have the shell ready before worrying about validation.

Step 2

Be pragmatic with validation

They do not need to use every validation type every time. Often four methods is enough, and some questions only ask for one.

Step 3

Know the file pattern

Fixed-width records with .ljust() help when multiple records are stored. Single-value save/recall is simpler and suits 2019 and 2025-style tasks.

Exam approach

Students should not aim for the most sophisticated code. They should aim for code that is clear, quick to build, and matches the wording of the task. In many papers, each validation technique only earns one mark up to a maximum, so there is no need to overcomplicate the solution if time is tight.

2. Sequential Inputs

Rather than writing a separate function for every single input, students can input values one after another inside the same procedure, just like your pets solution.

Teaching point: this is often a better exam approach because it is faster to write and easier for students to follow under timed conditions.

def add_pet():
    valid = False
    while valid == False:
        pet_id = input("Pet ID (1-10): ")
        if 1 <= len(pet_id) <= 10:
            valid = True
        else:
            print("Pet ID must be 1-10 characters.")

    valid = False
    while valid == False:
        name = input("Full Name (1-30): ")
        if 1 <= len(name) <= 30:
            valid = True
        else:
            print("Full name must be 1-30 characters.")

    valid = False
    while valid == False:
        species = input("Species (1-20): ")
        if 1 <= len(species) <= 20:
            valid = True
        else:
            print("Species must be 1-20 characters.")

    # create record and save afterwards

Why this works well

  • It keeps all inputs in one place.
  • Students can clearly see the order of fields.
  • It is easier to adapt in the exam if the field names change.
  • It avoids lots of small functions that can feel slower to build.

3. Validation Choices

Students need to know several validation methods, but they also need to be selective. Use what the question asks for, or what gives enough marks quickly.

Common validation types

  • Presence: cannot be blank
  • Length: min or max number of characters
  • Type: integer, float, letters only
  • Range: between a minimum and maximum value
  • Format: starts with a letter, contains a space, fixed pattern
  • Lookup / dictionary: value must be from a set list

Pragmatic exam advice

If the paper asks for four different validation techniques, students can stop at four. If the paper only asks for one type, there is no benefit in turning the program into something huge unless they have time.

4. Saving in a Fixed File Format

When a question needs several records to be stored and later searched, fixed-width storage using .ljust() is very useful.

Why use .ljust()?

  • Each field always starts at the same position.
  • That makes later retrieval with slicing much easier.
  • It suits questions where there may be many stored items.
record = (
    pet_id.ljust(10) +
    name.ljust(30) +
    nickname.ljust(20) +
    species.ljust(20) +
    dob.ljust(20) +
    size.ljust(10) +
    description.ljust(50) +
    "\n"
)

with open("pets.txt", "a") as file:
    file.write(record)

print("Pet details stored successfully.")

Key link: the way data is saved affects the way it must be searched later. If students save in fixed widths, they should retrieve using fixed slices.

5. Retrieving Data

Once students understand how the data was stored, retrieval becomes much easier. Fixed-width files lead naturally to slicing.

Retrieve and show all records

with open("pets.txt", "r") as file:
    for line in file:
        print("Pet ID:", line[0:10].strip())
        print("Full Name:", line[10:40].strip())
        print("Nickname:", line[40:60].strip())
        print("Species:", line[60:80].strip())
        print("Date of Birth:", line[80:100].strip())
        print("Size:", line[100:110].strip())
        print("Description:", line[110:160].strip())
        print("----------------------------")

Retrieve one matching record

search_id = input("Enter Pet ID to find: ")
found = False

with open("pets.txt", "r") as file:
    for line in file:
        if line[0:10].strip() == search_id:
            print("Pet ID:", line[0:10].strip())
            print("Full Name:", line[10:40].strip())
            found = True

if found == False:
    print("No matching record found.")

6. Saving One Item vs Saving Several Items

Not every paper needs fixed-width records. Some questions only need one value saved and recalled.

Several items stored

Used for customer, plumber or pet systems.

with open("pets.txt", "a") as file:
    file.write(record)
  • Use append mode "a".
  • Usually store one full record per line.
  • Often needs searching or displaying several records later.

One item stored

Used for 2019 and 2025-style save/recall questions.

with open("lastResult.txt", "w") as file:
    file.write(str(result))

with open("lastResult.txt", "r") as file:
    print(file.read())
  • Use write mode "w" when only the latest value matters.
  • Much simpler than fixed-width records.
  • No slicing is needed when recalling a single value.

Quick rule: if the exam asks for a list of records, think .ljust() and slicing. If it only asks to save the last result or last reading, just save one value to the file and read it back later.

def count_matching_plumbers():

KimsCalc

Full model solution for the calculator-style paper: two integer inputs from 0 to 9, three operations, display result, save, recall and clear.

def get_number(prompt):
    valid = False
    while valid == False:
        number = input(prompt)
        if not number.isdigit():
            print("Enter a whole number.")
        elif int(number) < 0 or int(number) > 9:
            print("Number must be between 0 and 9.")
        else:
            valid = True
    return int(number)


def save_result(result):
    with open("lastResult.txt", "w") as file:
        file.write(str(result))
    print("Result stored successfully.")


def recall_result():
    try:
        with open("lastResult.txt", "r") as file:
            print("Last result:", file.read())
    except FileNotFoundError:
        print("No saved result found.")


def clear_screen():
    print("Previous results cleared.")
    print("\n" * 10)


def main():
    option = ""
    result = 0

    while option != "6":
        print("\nKimsCalc")
        print("1. Add")
        print("2. Subtract")
        print("3. Multiply")
        print("4. Save Result")
        print("5. Recall Last Result")
        print("6. Exit")
        print("7. Clear Screen")

        option = input("Choose option: ")

        if option == "1":
            num1 = get_number("Enter first number (0-9): ")
            num2 = get_number("Enter second number (0-9): ")
            result = num1 + num2
            print("Result:", result)

        elif option == "2":
            num1 = get_number("Enter first number (0-9): ")
            num2 = get_number("Enter second number (0-9): ")
            result = num1 - num2
            print("Result:", result)

        elif option == "3":
            num1 = get_number("Enter first number (0-9): ")
            num2 = get_number("Enter second number (0-9): ")
            result = num1 * num2
            print("Result:", result)

        elif option == "4":
            save_result(result)

        elif option == "5":
            recall_result()

        elif option == "6":
            print("Calculator closed.")

        elif option == "7":
            clear_screen()

        else:
            print("Invalid option.")

AZSalt / Simple Save-Recall

Full model for the simpler 2025-style program: input one reading, output the correct message, terminate on 100, save the last reading and recall it.

def save_reading(value):
    with open("saltResult.txt", "w") as file:
        file.write(str(value))
    print("Last reading stored successfully.")


def recall_reading():
    try:
        with open("saltResult.txt", "r") as file:
            print("Last reading:", file.read())
    except FileNotFoundError:
        print("No saved reading found.")


def process_reading(current_level):
    if current_level < 0 or current_level > 10:
        print("fault detected")
    elif current_level > 6:
        print("add water")
    elif current_level >= 4:
        print("stop addition")
    elif current_level >= 2:
        print("add salt")
    else:
        print("double the salt addition")


def main():
    option = ""

    while option != "3":
        print("\nAZ Salt Monitor")
        print("1. Input Reading")
        print("2. Recall Last Reading")
        print("3. Exit")

        option = input("Choose option: ")

        if option == "1":
            valid = False
            while valid == False:
                reading = input("Enter salinity reading (or 100 to terminate): ")
                try:
                    current_level = float(reading)
                    valid = True
                except ValueError:
                    print("Enter a valid number.")

            if current_level == 100:
                print("program terminated")
                option = "3"
            else:
                process_reading(current_level)
                save_reading(current_level)

        elif option == "2":
            recall_reading()

        elif option == "3":
            print("System closed.")

        else:
            print("Invalid option.")


main()
