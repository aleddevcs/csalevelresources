Core Exam Definition

A data structure is a way of organising and storing data so that it can be accessed, processed and modified efficiently.

Primitive data types: integer, real/float, character, Boolean and pointer.
Static structures: fixed size, e.g. arrays.
Dynamic structures: can grow/shrink, e.g. linked lists.

1. Arrays up to Three Dimensions

An array stores multiple related items of the same data type under one identifier. Arrays are usually indexed from 0 and allow direct access using an index.

1D Array

A single row/list of values.

OUTPUT words[2]
// Displays "sugar"

2D Array

A table of rows and columns.

OUTPUT data[1][3]
// Displays "because"

3D Array

Layers of 2D arrays.

OUTPUT game[year][level][word]
// Accesses a value in a 3D array

Exam Focus

  • Use an index to access or update a value.
  • Use nested loops for 2D and triple nested loops for 3D arrays.
  • Arrays are fixed size in many exam contexts.
  • WJEC examples may use either row-column or column-row references, so be consistent with the question.
FOR i = 0 TO rows - 1        // outer loop: rows
    FOR j = 0 TO columns - 1  // inner loop: columns
        OUTPUT array[i][j]
    NEXT j
NEXT i
Memory aid: Array = numbered boxes. 2D = table. 3D = layers of tables.

2. Stacks and Queues Using Pointers and Arrays

Stack – LIFO

Last In, First Out. The last item pushed is the first item popped.

  • Pointer: top
  • Uses: undo, function calls, recursion

Queue – FIFO

First In, First Out. The first item enqueued is the first item dequeued.

  • Pointers: front and rear
  • Uses: print queues, order processing, scheduling
Stack memory aid: stack of plates → last plate on is first plate off.
Queue memory aid: line of people → first person in line is served first.

3. Hash Tables

A hash table stores data as a key-value pair. A hashing algorithm calculates an index, often using MOD. This can provide direct access, but collisions must be handled.

Interactive Hashing Example

Hash function: index = key MOD 10

Exam Focus

  • Collision: when two keys generate the same index.
  • Linear probing: check the next available location.
  • Separate chaining: store a linked list at the hash index.
  • Separate chaining can slow retrieval because the linked list may also need searching.
  • Linear probing can cause clustering if many collisions occur.
Memory aid: Hash = calculate a shortcut location. Collision = two students trying to sit in the same seat.

4. Linked Lists Using Pointers and Arrays

A linked list is a dynamic data structure made of nodes. Each node stores data and a pointer to the next node.

Interactive Ordered Linked List

Exam Focus

  • Adding/deleting changes pointers rather than shifting all elements.
  • Linked lists do not provide direct access; they must be traversed.
  • Sorted linked lists allow searches to stop early.
  • Unsorted linked lists may require searching the whole list.
SET current = head WHILE current ≠ NULL OUTPUT current.data SET current = current.next END WHILE
Advantages: dynamic size, efficient insertion/deletion, no need to pre-allocate fixed size.
Disadvantages: sequential access, extra memory for pointers, difficult reverse traversal in singly linked lists.

5. Binary Trees and Traversals

A binary tree is a hierarchical data structure where each node has up to two children. A binary search tree places smaller or equal values to the left and greater values to the right.

Example Tree

        F
      /   \
     B     G
    / \     \
   A   D     I
      / \   /
     C   E H

Choose a traversal.

Traversal Rules

  • In-order: Left, Root, Right. Used to output/search a BST in order.
  • Pre-order: Root, Left, Right. Useful for copying a tree.
  • Post-order: Left, Right, Root. Useful for deleting a tree.

Balanced vs Unbalanced

A balanced tree keeps operations such as add, delete and find closer to logarithmic time. An unbalanced tree can degrade towards linear time.

Leaf deletion: remove the node.
One child: link the parent directly to the child.
Two children: replace with in-order predecessor or successor, then delete that node.
Memory aid: Pre = root first. In = root in the middle. Post = root last.
