Building a Fixed-Length Record

~10 minutes

BEAT 1 · WHY FIXED WIDTH

Say: "Right now our fields are all different lengths. If we just join them together, we won't be able to tell where one field ends and the next begins when we read the file back later."

.ljust(width) pads a field with spaces up to a set width — so every record has fields in exactly the same position, every time.

BEAT 2 · LIVE-CODE THE RECORD STRING

Say: "Let's build one record string from our three fields."

record = (
    name.ljust(20) +
    kayak.ljust(15) +
    date.ljust(10)
)

print(record)
Expect: One long string, each field padded with trailing spaces to its fixed width

BEAT 3 · CHECK UNDERSTANDING

Ask: "What would go wrong later if we picked a width too small for a long name?" — get at least one answer (truncation / fields running together) before moving on.

Saving to a File

~10 minutes

BEAT 1 · LIVE-CODE OPEN & WRITE

Say: "Open the file in append mode, write the record, then close it."

file = open("kayak_hires.txt", "a")
file.write(record + "\n")
file.close()

print("Saved!")
Expect: No visible output beyond "Saved!" — the file is written silently

BEAT 2 · PROVE IT WORKS

Say: "Let's run add_record() twice in the same session, then open the file together."

Expect: Two lines in kayak_hires.txt, one per run — neither overwriting the other
Common slip: Using "w" instead of "a" silently erases every earlier record each time the file is opened. Worth demonstrating deliberately once, so students recognise the symptom.

BEAT 3 · HAND OVER TO THE BUILD TASK

Students now do the same thing to their own validated add_record() — build a record string, write it in append mode, and test with two records before moving to the Whiteboard.
